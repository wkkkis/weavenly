# Weavenly — серверная часть

## Коротко

Приложение работает на компьютере пользователя. Серверу оставлены три задачи: **публичный индекс
вакансий** (его раз в 8 часов собирает GitHub Actions), **данные H-1B и грин-карт** (раз в месяц из
файлов Министерства труда США) и **недельный отчёт о найме** (по понедельникам, из индекса). Все три
публикуются статическими файлами на `https://index.weavenly.app/v1/`.
Это не API: у файлов нет пользователей, запросов и id, они одни и те же для всех. Приложение скачивает их и
подбирает вакансии и работодателей у себя.

Ещё в `backend/` лежит вход по magic-link (Fastify + Postgres). Приложение им не пользуется, единственный
клиент — страницы `/signin` на сайте.

Резюме, ответы на вопросы форм, почта, AI-запросы, роли и поиски **никогда** не уходят на наш сервер.

## Чего на сервере нет (и почему)

### ❌ Отклики с сервера
- **Юридически**: LinkedIn vs hiQ Labs (2017–2022) — LinkedIn выиграл. Серверная автоматизация и скрейпинг
  нарушают TOS Indeed, LinkedIn и Workday.
- **Практически**: фингерпринтинг ловит IP, заголовки и тайминги; понадобился бы пул residential-прокси.
- **Репутация**: бан аккаунта пользователя с нашего IP — это наша вина.
- **Как сделано**: формы заполняет расширение в браузере самого пользователя, Submit жмёт он сам.

### ❌ Доступ к почте на сервере
- Почта читается по IMAP прямо из приложения, письма отправляются по SMTP. Вход — паролем приложения
  (Gmail, Yandex, Mail.ru, iCloud, Yahoo или свой сервер). Пароль хранится в keychain ОС
  (`app/src/email/account.ts` → `secret-store.ts`).
- Вход через Google (OAuth, Gmail API) убран 2026-10-15, так что проверка Google и аудит CASA больше не
  нужны (`app/docs/superpowers/specs/2026-10-15-mail-imap-design.md`).

### ❌ Резюме и личные данные на сервере
- Это убило бы главное обещание продукта: всё хранится у пользователя.
- GDPR и CCPA, риск утечки.

### ❌ Поиск по запросу пользователя
- Индекс не знает, что ищет пользователь. Приложение скачивает семейства профессий целиком, а фильтрует
  у себя. Даже удалённые доски (Himalayas и другие) приложение читает без поисковых слов
  (`app/src/discovery/boards.ts`).

## Публичный индекс вакансий

Код — `backend/src/job-index/`, запуск — `.github/workflows/job-index.yml`, дизайн —
`app/docs/superpowers/specs/2026-10-13-job-discovery-design.md`.

```
GitHub Actions, cron '15 */8 * * *' (каждые 8 часов; первый прогон понедельника — недельный)
  backend: index:build --publish
    catalog/companies.csv (~37 000 досок) + состояние из прошлого прогона
      → публичные списки вакансий ATS (60 досок параллельно, бюджет 25 минут)
      → строки без описаний → шарды по семействам профессий → gzip + sha256
      → Cloudflare R2 → https://index.weavenly.app/v1/
           manifest.json
           jobs/<family>.v1.<sha256-префикс>.json.gz
           (state/companies.csv.gz — состояние каталога для следующего прогона)

Компьютер пользователя (main-процесс приложения): через 30 с после старта, потом каждые 6 часов
(настройка, 1–24) и по кнопке «Обновить»
  manifest.json (ETag) → только изменившиеся шарды нужных ролям семейств
  + пять удалённых досок раз в день (Himalayas, Arbeitnow, Remotive, Remote OK, We Work Remotely)
  → фильтр по роли → оценка по заголовку → топ-50
  → полное описание из фида работодателя (30 новых за прогон) → сравнение с резюме роли
  → AI-оценка в пределах дневного лимита (10 на роль в день, 0 — выключено)
  → data/discovery/<roleId>.json → вкладка «Найдено» на странице Jobs, шаг на Home, уведомление раз в день
```

**Источники** — только публичные списки вакансий без ключей и логина, которые не закрыты в robots.txt:

| ATS | Читаем |
|---|---|
| Greenhouse, Lever (и его EU-хост), Ashby, Workable, SmartRecruiters, Recruitee, Personio | ✅ фиды для job board'ов |
| Teamtailor, Breezy, Pinpoint, BambooHR, Rippling | ✅ открытые списки, из которых строятся их страницы вакансий |
| Workday | ✅ поиск сайта вакансий компании (POST, 20 на страницу, не больше 1000 на доску) |
| LinkedIn, Indeed, Glassdoor, hh.ru | ❌ никогда |

**Каталог.** Начальный список — `kalil0321/ats-scrapers` (MIT, `backend/catalog/NOTICE`). Доска бывает
`live` (читается каждый прогон), `cold` (вакансий нет 30 дней — читается раз в неделю) и `dead` (два 404
подряд или 21 неудачное чтение подряд, примерно неделя — читается в первый недельный прогон месяца, её
строки уходят из индекса). Ответ 422 от Workday (такого клиента нет) и редирект BambooHR со списка на
главную или вход тоже значат, что доски нет. Недельный прогон ещё ищет новые доски в индексе URL Common
Crawl (до 2000 проверок, по очереди для каждой ATS).

**Честность.** User-Agent `WeavenlyJobIndex/1.0 (+https://weavenly.app/jobs-index; hello@weavenly.app)`,
не больше 5 запросов к одной ATS одновременно (у Workday — к одному дата-центру), `Retry-After`
соблюдается. Страница
`weavenly.app/jobs-index` объясняет, что это, и как компании убрать себя из индекса
(`backend/catalog/excluded.txt`).

**Формат** — `backend/src/job-index/format.ts`, версия 1. Строка: ключ, заголовок, компания, ATS, slug, id,
место, страны, формат работы, зарплата (если есть), дата публикации, дата первого появления, ссылка на
вакансию и на форму. Описаний нет. Файл побайтно скопирован в `app/src/discovery/index-format.ts`;
`.github/workflows/job-index-format.yml` падает, если копии разошлись.

**Безопасная публикация.** Неизменившееся семейство сохраняет прежний файл (приложение не скачивает его
заново). Манифест пишется последним, файлы, на которые не ссылаются ни новый, ни старый манифест,
удаляются. Если опубликованный индекс не прочитался, новый не публикуется: иначе строки потеряли бы даты
первого появления.

## Данные H-1B и грин-карт

Код — `backend/src/visa/`, запуск — `.github/workflows/visa-data.yml`.

```
GitHub Actions, cron '40 4 3 * *' (3-го числа каждого месяца)
  backend: visa:build --fetch --publish
    страница https://www.dol.gov/agencies/eta/foreign-labor/performance → самые новые файлы
    LCA_Disclosure_Data_FY<год>_Q<n>.xlsx и PERM_Disclosure_Data_FY<год>_Q<n>.xlsx
      (если опубликованные данные уже из этих файлов — на этом всё)
      → строки по одной (потоковое чтение xlsx): только H-1B, у которых статус начинается с Certified
        (и Certified - Withdrawn), у PERM так же
      → работодатель по ключу названия (employerKey) → профессия (SOC) → штат:
        заявки, уровни зарплаты I–IV, медиана предложенной годовой зарплаты, новые сотрудники и переходы;
        грин-карты по профессиям; торговые названия → ключ работодателя
      → gzip + sha256 → Cloudflare R2 → https://index.weavenly.app/v1/
           visa/manifest.json
           visa/h1b.v1.<sha256-префикс>.json.gz

Компьютер пользователя: при каждом запуске поиска — манифест по ETag, файл только при новом sha256
  → под американской вакансией строка: заявки работодателя на такую роль в штате вакансии, уровень,
    медиана зарплаты, грин-карты (не видна, если в «О себе» сказано, что спонсорство не нужно)

Сайт: при каждой сборке на Vercel (раз в день её запрашивает .github/workflows/site-refresh.yml)
  visa/manifest.json → файл + манифест и шарды индекса
  → /h1b и страница на каждого работодателя с 20+ заявками: роли, штаты, уровни, грин-карты, открытые
    вакансии в США из индекса
```

Файлы Министерства труда — открытые данные (public domain), имён работников в них нет. Сборщик берёт из
заявки только работодателя, профессию, штат, уровень, зарплату и тип найма. `dol.gov` отдаёт файлы `curl`,
но не HTTP-клиенту Node, поэтому сборщик скачивает их `curl`.

**Формат** — `backend/src/visa/format.ts`, версия 1, побайтно скопирован в `app/src/discovery/visa-format.ts` и
`frontend/src/lib/visa-format.ts`; `.github/workflows/job-index-format.yml` сравнивает и эти копии. Манифест пишется после файла, старые файлы
удаляются, кроме того, на который ссылался прежний манифест.

## Недельный отчёт о найме

Код — `backend/src/report/`, запуск — `.github/workflows/hiring-report.yml`.

```
GitHub Actions: после каждого прогона job-index.yml, который закончился в понедельник (UTC),
и запасной cron '41 12 * * 1' (если неделя уже опубликована — на этом всё)
  backend: report:build --publish
    manifest.json и все шарды индекса (по sha256) + данные H-1B + отчёт и доски прошлой недели
      → вакансии, которые индекс впервые увидел (f) за прошедшую неделю, с понедельника по воскресенье UTC,
        только на досках, которые он читал до начала недели
      → по семействам, штатам США и компаниям; доля удалённых; зарплата (только на системах, чьи списки
        её содержат); доля вакансий в США у работодателей с заявками H-1B (employerFinder, как в приложении)
      → изменение к прошлой неделе по доскам, учтённым в обоих отчётах; дни, когда индекс ничего не публиковал
      → посты для LinkedIn и Threads на английском и русском по шаблонам (без AI), они же в сводке прогона
      → Cloudflare R2 → https://index.weavenly.app/v1/
           report/weekly-<год>-W<неделя>.json
           report/boards-<год>-W<неделя>.json.gz (новые вакансии каждой доски, для сравнения через неделю)
           report/index.json (все недели, новые сверху; пишется последним)
  → хук Vercel (VERCEL_DEPLOY_HOOK, если задан): новая сборка сайта

Сайт: при каждой сборке report/index.json и файл каждой недели
  → /hiring-report (последняя неделя) и /hiring-report/<год>-w<неделя>, на английском и русском
```

«Новая» значит впервые увиденная индексом, а он читает только карьерные страницы компаний на тех ATS, что
перечислены выше. Когда индекс начинает читать новую доску, все её открытые вакансии для него новые, хотя
большинство опубликованы раньше: такие доски и их вакансии показаны отдельно и в цифры не входят. Сравнение с
прошлой неделей идёт только по доскам, учтённым в обоих отчётах, чтобы рост числа досок не выглядел ростом
найма. Старые недели не удаляются.

**Формат** — `backend/src/report/format.ts`, версия 1, побайтно скопирован в `frontend/src/lib/report-format.ts`;
`.github/workflows/job-index-format.yml` сравнивает копии.

## Вход по magic-link

- `backend/src/auth/`: `POST /auth/request` (письмо через Resend; без ключа ссылка печатается в
  терминал), `GET /auth/verify` (выдаёт JWT), `GET /me`.
- Postgres: `users` (`tier` всегда `free`) и `magic_tokens` (одноразовые, 15 минут).
- 5 запросов на email в час, счётчик в памяти (только один экземпляр). Без `JWT_SECRET` в production
  сервер не стартует.
- Приложение этим входом не пользуется. Если понадобится серверная функция для аккаунта — она будет здесь.

## Деньги

**Приложение и расширение бесплатны. Платных функций нет.** Серверного автоотклика не будет (см. выше).
Stripe, предзаказы и подписки удалены.

AI работает на ресурсах пользователя: его подписка ChatGPT или Claude, его ключ Anthropic или OpenAI, либо
локальный Ollama. Нашего прокси нет.

> **Монетизация отложена.** Если когда-нибудь появится платное, то это опциональный hosted-AI
> (ключ под управлением Weavenly для тех, кто не хочет подключать свой) на провайдере, бережном к
> приватности. Он никогда не закроет собой локальное приложение — оно остаётся бесплатным.

## Что не сделано

- Sign-in API: общий rate limit для нескольких экземпляров, Sentry/OpenTelemetry.
- Идеи, не начатые: зарплатные данные по компании, Slack-вебхук на новые совпадения, недельный дайджест.
